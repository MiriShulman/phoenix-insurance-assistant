# גרסת RAG בסיסית — עוזר הפניקס

## מה השתנה

- חלוקת עמודי המאגר לקטעי טקסט (chunks).
- חיפוש מקומי מבוסס TF-IDF ברמת הקטע, עם שילוב התאמת מילים ו-n-grams של תווים כדי להתמודד טוב יותר עם הטיות ואיות בעברית.
- שימוש בקטע שאוחזר כמקור לתשובה, במקום לבחור קטע אקראי מתוך עמוד שלם.
- סף מינימלי לראיות: כשאין התאמה מספקת, הבוט אומר שלא נמצא מקור מספיק רלוונטי.
- העברת היסטוריית השיחה האחרונה מה-React לשרת, כדי לתמוך טוב יותר בשאלות המשך.
- תמיכה אופציונלית במודל שפה דרך API תואם OpenAI. ללא מפתח, המערכת ממשיכה לפעול באמצעות מנגנון התשובות המקומי הקיים.

## התקנה מקומית ב-Windows

בחלון PowerShell ראשון:

```powershell
cd "נתיב-לפרויקט\server"
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
uvicorn main:app --reload
```

בחלון PowerShell שני:

```powershell
cd "נתיב-לפרויקט\client"
npm install
npm run dev
```

פתחי את כתובת Vite שמופיעה בטרמינל, בדרך כלל `http://localhost:5173`.

## בדיקת השרת

פתחי `http://127.0.0.1:8000/health`. צפוי להופיע JSON עם `pages_loaded`, `retrieval` ו-`llm_configured`.

אפשר לבדוק שאלה דרך `http://127.0.0.1:8000/docs` או דרך ממשק הצ'אט.

## מודל שפה (אופציונלי)

כרגע אין צורך במפתח API כדי לבדוק את האחזור המקומי. כדי להפעיל יצירת תשובות באמצעות מודל תואם OpenAI, הגדירי משתני סביבה **בשרת בלבד**:

```powershell
$env:LLM_API_KEY="המפתח שלך"
$env:LLM_MODEL="שם-המודל"
$env:LLM_BASE_URL="https://api.openai.com/v1"
uvicorn main:app --reload
```

אין לשמור מפתחות בקוד, ב-React או ב-Git. ב-Render יש להגדיר אותם ב-Environment של שירות ה-Backend. ללא `LLM_API_KEY` ו-`LLM_MODEL`, תופעל תשובת הגיבוי המקומית.

## מגבלה חשובה

הגרסה הזאת מוסיפה אחזור RAG מקומי ברמת קטעים, אבל מנגנון החיפוש הוא TF-IDF ולא מודל Embeddings סמנטי. יצירת תשובות בעזרת LLM מופעלת רק אם מוגדר ספק מודל ומפתח. לכן, ללא הגדרות אלה, זו גרסת בסיס חינמית עם תשובות מבוססות מקורות — לא יצירה גנרטיבית מלאה.
